<details>
<summary><strong>Auth Backend — Enterprise JWT Authentication Service</strong></summary>

<br/>

Production-grade stateless authentication microservice built with Spring Boot 3 and PostgreSQL. Implements self-issued JWTs using HMAC-SHA512, full refresh-token rotation with JTI-based revocation audit trails, Google OAuth2 via Spring Security's OAuth2 Client, and HTTP-only cookie delivery — all documented via SpringDoc OpenAPI (Swagger UI).

| Attribute | Detail |
|:---|:---|
| **Stack** | Java 21 · Spring Boot 3.5 · Spring Security 6 · jjwt 0.13 · PostgreSQL |
| **Architecture** | Stateless resource server · OncePerRequestFilter JWT validation |
| **Security** | HMAC-SHA512 · HTTP-only + Secure + SameSite=Lax cookies · BCrypt |
| **Token Design** | Access (10 min) + Refresh (24 hr) · `typ` claim prevents token confusion |
| **Rotation** | JTI revocation chain: `replacedByToken` field traces full refresh history |
| **API Docs** | SpringDoc OpenAPI · Swagger UI at `/swagger-ui.html` |
| **Impact** | Drop-in auth service reusable across any Spring Boot or React project |
| **Repository** | [![GitHub](https://img.shields.io/badge/guptaaayansh%2Fauth--backend--springboot-181717?style=flat-square&logo=github&logoColor=white)](https://github.com/guptaaayansh/auth-backend-springboot) |

Refresh token reads from four sources in priority order: HTTP-only cookie → request body → `X-Refresh-Token` header → `Authorization: Bearer` header — making it compatible with browser clients (cookie), mobile apps (header), and API tooling (body) without changing the contract.

</details>

<details>
<summary><strong>TicketHub — Full-Stack Event Ticketing Platform</strong></summary>

<br/>

End-to-end event ticketing system with three distinct user personas (Organizer, Attendee, Staff), Keycloak OIDC identity, QR-code-backed tickets generated via ZXing, and a full React/TypeScript frontend with role-based route guards. Docker Compose orchestrates PostgreSQL, Adminer, and Keycloak locally.

| Attribute | Detail |
|:---|:---|
| **Stack** | Java 21 · Spring Boot 3.4 · React 19 · TypeScript · PostgreSQL · Keycloak |
| **Architecture** | Layered: Controller → Service → Repository → Entity · MapStruct DTOs |
| **Security** | Keycloak OIDC · Spring Security OAuth2 Resource Server · JWT validation |
| **Transactions** | `@Transactional` purchase flow: inventory decrement + ticket + QR atomically |
| **QR Pipeline** | ZXing MultiFormatWriter → UUID string → PNG byte array → DB entity |
| **Frontend Auth** | keycloak-js `check-sso` · Axios interceptor · `ProtectedRoute` role guards |
| **Performance** | `UserProvisioningFilter` auto-provisions DB users from JWT on first request |
| **Repository** | [![GitHub](https://img.shields.io/badge/guptaaayansh%2Fticket--booking--system-181717?style=flat-square&logo=github&logoColor=white)](https://github.com/guptaaayansh/ticket-booking-system-java-fullstack) |

Notable engineering decision: `UserProvisioningFilter` bridges the stateless JWT world with the relational DB world — on every authenticated request, it checks for a local `User` row by `keycloakId`, creating one if absent, so downstream services always operate on a real DB entity rather than a raw JWT claim.

</details>
